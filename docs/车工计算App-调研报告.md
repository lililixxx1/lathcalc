# 车工计算类 App 调研报告（v2）

> 调研日期：2026-11-03　｜　定位：为「开源免费、面向普通车工师傅、够用不专业」的手机计算 App 做决策
> 方法与证据等级：优先一手来源（App Store / 应用宝页面原文、GitHub API）；下载站、淘宝、论坛为旁证；推断处标注，未查到的如实写"未查到"。
> 版本说明：v2 合并了两次独立调研——A（应用宝 + App Store 一手抓取、`cnc-turner-friend` 功能地图）与 B（国际 App 12 款、17 个开源仓库逐个核实）。**价格/评分/star 均为当日快照，会变动。**

---

## 0. 一页结论

1. **需求是真的，市场是小的**：国内头部也就 7 万下载（车工计算）、4 万（数控宝典）、2 万（数控车工计算），整个品类每年撑起的营收大概在几十万到几百万量级，被 5–6 家小公司分掉。这不是一个能靠它发财的赛道，但是一个**口碑极强、复购极稳**的刚需工具。
2. **国内套路高度一致**：免费下载 + VIP 锁"高级计算"，锁的恰恰是**螺纹程序生成、宏程序、圆弧切点**这些最高频的刚需；年费 ¥58–60，也有 ¥28/¥38 买断的。衍生了淘宝卖激活码和"破解版"下载站——这是付费墙逼出来的需求。
3. **差评非常集中，且每一条都是开源产品的卖点**：VIP 锁资料还贵（数控车床CNC宝典 **2.0 分**，评论直接说"68 有点偏高"）、"算个数还要连服务器"、切点图形太少、换手机要重买。
4. **两个市场各有半张牌**：国内款会**生成程序**（G76/宏）但**没人做材料切削参数库**；国际款有**材料×刀具×工序参数库**（FSWizard 200+ 材料、CNC MCP 170+）但**几乎不碰宏程序/程序生成**。**"国际型参数库 + 国内型程序生成"这个组合，两个市场都没人做。**
5. **开源侧是空白，但不是荒地**：核实 17 个仓库，**没有一个活跃的、中文的、面向手机的车工综合 App**（唯一的 Android 原生项目 2017 年就死了，无 Flutter/RN 实现，F-Droid 空白）；中文唯一"全家桶"是网页版 `cnc-turner-friend`，但**无 LICENSE、无移动端**。可放心复用代码的只有 6 个 MIT/MIT-0 项目。
6. **一个额外窗口期**：国际付费头部 **G-Wizard 于 2024 年因创始人去世停售停更**，源码未随遗产出售——"选材料→出参数"的需求留下供给空档。

**一句话定位建议**：
> 一个**完全离线、无广告、无登录、全功能免费**的中文车工计算器：把国内"六件套"做全并**免费放开程序生成**，再补上国内没人做的**国产材料切削参数库**（45 钢/40Cr/HT200…），切成点图形要"量足"。

**做/不做的判断**：值得做，但**按"做完就够用的小工具"来做**，不要按"要赚钱的产品"来做。它的价值在口碑、在社区、在你自己的技术积累，不在订阅收入。

### 2.3 商业判断（决定你该用什么姿势做）

- **天花板低**：整个品类头部 7 万下载，付费转化按 3–5% 算，年营收几十万级。**做付费版，投入产出比不划算。**
- **但用户愿意付费**：能养活 5–6 家小公司，说明"省时间"这件事值钱——只是他们收得不体面。
- **所以最优解是开源**：用"免费 + 全功能 + 离线"吃掉所有差评对应的需求，赢得师傅圈子信任；变现走**赞助/定制/技术影响力**，而不是订阅。
- **风险提示**：正因为它便宜（¥28 买断），你的免费版不会"杀死"竞品，也别指望它带来收入。**把它当作品，别当生意。**

### 3.5 三种值得"抄方法论"而不是抄代码的东西

1. **架构**（Machinist_calc）：`calc-core.js` 纯核心 + UI 分离 + 断言测试 + CI。你的 App 照这个骨架走，永远不会烂。
2. **数据治理**（ThreadBuddy）：`PROVENANCE.md` 记"这个数从哪本标准、哪一版来"，`COVERAGE.md` 记"覆盖了哪些规格、还缺哪些"。**这是让社区敢信你、敢提 PR 的关键。**
3. **交互尺寸**（Machinist_calc）：44px 触控目标、公英制含分数输入。车间场景的硬指标。

### 3.6 空缺清单（= 你的机会）

| # | 空缺 | 置信度 |
|---|---|---|
| 1 | **没有活跃的、面向手机的车工综合计算 App**（Android 原生仅 1 个且死于 2017；无 Flutter/RN；F-Droid 空白） | 高 |

## 4. 功能需求

### 4.1 P0 · 六件套（不做就不算车工 App）

| # | 模块 | 输入 → 输出 | 关键公式 / 数据来源 | 易错点 |
|---|---|---|---|---|
| 1 | **转速 ↔ 线速度** | D、Vc 或 n、f → n、vf、G98/G99、理论 Ra | `n=1000Vc/(πD)`；`vf=f·n`；`Ra≈1000f²/(8r)` | 单位（m/min vs mm/min）；G98/G99 混用 |
| 2 | **螺纹查询计算** | 类型（M/UNC/UNF/G/R/Tr/蜗杆/NPT）+ 规格或自定义 → 中径/小径/牙高/底孔/三针 | 60°：`d2=d−0.6495P`、`d1=d−1.0825P`、牙型高 `0.866P`、工作牙高 `0.5413P`；55°：`d2=d−0.6403P`、`d1=d−1.2806P`；Tr 按 GB/T 5796（牙型角 30°、牙高 0.5P）；三针 60° `M=d2+3d0−0.866P`、55° `M=d2+3.1657d0−0.9605P` | 底孔用 `d−P` 近似仅适用部分材料；管螺纹按每英寸牙数换算 P；NPT 是 1:16 锥 |
| 3 | **螺纹/零件程序生成** | 上一步参数 + 系统类型 → G76/G92 程序（可复制） | FANUC 两行式 G76 模板；宏程序（椭圆/网纹/油槽） | 牙高单位是 μm；P/Q/R 含义各系统不同；必须标"仅参考" |
| 4 | **圆弧切点** | 工况图选型 + 已知尺寸 → 切点 (X,Z)、圆心、G02/G03 | 圆心到直线距离 = R；两圆心距 = R1±R2；刀补按 T1–T9 方位号 | **图形数量**（竞品最大差评）；内外圆弧方向判反 |
| 5 | **锥度** | D/d/L 任给三个 → C、半角、起退刀坐标 | `C=(D−d)/L`；`α/2=arctan((D−d)/(2L))`；莫氏 0–6 查表（GB/T 1443，锥度约 1:19.2–1:20.05，半角约 1°29′） | 半角 vs 全角；内外锥符号 |
| 6 | **公差 + 三角 + 重量** | 尺寸+IT+配合 / 三角形三边三角 / 形状+尺寸+材质 → 偏差表、余项、重量 | **GB/T 1800.1 直接内置表**（分段+圆整，别用近似公式）；正弦/余弦定理；`m=ρV` | IT 表跨段插值；密度取 7.85（钢）/7.93（不锈）/2.70（铝）/8.5（黄铜） |

### 4.2 P1 · 差异化（别人收费或没人做）

| 项 | 为什么做 | 备注 |
|---|---|---|
| **国产材料切削参数库** | **国内 0 家免费做**，国际款只做欧美牌号；叠加 G-Wizard 退市窗口 | 45 钢/40Cr/40CrMo/HT200/QT450/304/316/6061/7075/黄铜…选材料→出 Vc/f 推荐区间。**必须标"推荐值，试切为准"并记录数据来源** |
| **攻丝底孔 / 钻头丝锥表** | 高频、纯静态、成本极低 | 切削丝锥 vs 挤压丝锥底孔不同 |
| **挂轮计算** | 普通车床师傅刚需；开源只有 `gears` 一个且只覆盖国产小车床 | 适配常见国产车床齿轮配置（63/64/66/72/80/90/100…） |
| **刀尖半径补偿** | 锥度/圆弧/螺纹不带补偿就过切，是"专业度分水岭" | 补偿开关 + 刀尖方位号 T1–T9 |
| **公英制换算（含分数英寸）** | 老图纸大量 1/2″、5/16″ | 分数输入/显示 |
| **收藏 / 历史 / 计算书分享** | 师傅干重复活；长图发微信群是天然传播 | 本地存储，不上云 |

### 4.3 P2 · 锦上添花

G/M 代码速查、工时估算、硬度换算（HRC/HB/HV）、刀具库、切槽/切断计算、圆等分/多边形对角、中心孔、粗糙度对照、**工艺品宏程序**（五角星/心形/葫芦——**不产生生产价值，但是抖音传播钩子**，放"玩一玩"里）。

### 4.4 明确"先不做"

- 3D 仿真/刀路预览（成本高、竞品也没做好，`cnc-turner-friend` 的宏转 G 模拟已是上限参考）
- 云同步/账号体系（违背"离线无登录"定位）
- 报价/工时管理（那是 ERP 的活）
- 多语言（先中文，日韩以后再说）

### 4.5 五条交互铁律（竞品全都没做到，做到就赢一半）

1. **结果旁必须显示"怎么算的"**：公式 + 代入数值 + 依据标准号（如 GB/T 196）。师傅不怕你算错，怕的是他不知道你对不对。
2. **输入即算**，不要"计算"按钮。
3. **自绘大数字键盘**：带 ±、小数点、退格、分数输入；44px+ 触控目标；戴手套也能按。
4. **完全离线**：数据全打包，无网络权限、无登录、无广告、无埋点。
5. **一处输入，多处复用**：算完的螺纹参数一键带到 G 代码 / 三针 / 底孔。

## 6. 技术方案

### 6.1 选型对比

| 方案 | 优点 | 缺点 | 判断 |
|---|---|---|---|
| **PWA**（纯静态 + 可安装） | 一周出可用版；扫码即用、加到主屏离线跑；微信群里传得开；迭代零成本 | 安卓商店上架受限；iOS 体验略逊原生 | **第一阶段首选**（Machinist_calc / ThreadBuddy 都是这条路，验证有效） |
| **Flutter** | 双端一套代码；绘图（切点示意图）强；性能/手势好；打包成熟 | 包体 15–25MB；需装环境 | **第二阶段上架用** |
| React Native / Expo | 前端栈友好 | 数值键盘/绘图要额外处理 | 你熟 React 再考虑 |
| 原生 Kotlin | 最轻、最顺 | iOS 要重写 | 只做安卓时可选 |

### 6.2 推荐路径（两阶段，别一步到位）

```
阶段一（1–2 周）：PWA 版，只做 4 个最高频模块
        ↳ 转速换算、螺纹查询、锥度、公差+三角
        ↳ 给 2–3 位师傅试用，只问三个问题：算得对不对、找不找得到、按不按得动
阶段二（3–6 周）：补齐切点 + 程序生成 + 材料参数库 → Flutter 包壳上架
```

> 理由：程序生成工作量最大但也是最强传播点，**放到第二个迭代**；先用 4 个模块验证"师傅愿不愿意在手机上用它"。

### 6.3 仓库结构（公式归公式、数据归数据）

```
core/            纯函数，零 UI 依赖，可单测
  speed.dart       转速/进给/粗糙度
  thread.dart      螺纹（各标准常数、底孔、三针）
  taper.dart       锥度 / 莫氏
  arc.dart         圆弧切点（每种工况一个函数）
  tolerance.dart   公差查表 + 配合
  weight.dart      重量
  gcode.dart       G76/G92/宏程序模板
data/            纯 JSON，非程序员也能改
  threads_metric.json / _unix.json / _pipe.json / _trapezoid.json
  tolerance_it.json / fits.json / morse.json / materials.json
  cutting_speeds.json / gcode_ref.json
  PROVENANCE.md    每个文件的来源、标准号、版本、录入人
  COVERAGE.md      已覆盖规格 / 待补规格
ui/              页面（PWA 期是 HTML，Flutter 期是 Widget）
test/            **黄金用例**：每个公式 ≥3 组手册例题对拍
```

### 6.4 测试策略：拿"标准答案"锁死正确性

| 模块 | 黄金用例（可直接写进测试） |
|---|---|
| 螺纹 M30×2 | d2 = 30 − 0.6495×2 = **28.701**；d1 = 30 − 1.0825×2 = **27.835**；底孔 ≈ **28.0** |
| 三针 M30×2（d0=1.1547） | M = 28.701 + 3×1.1547 − 0.866×2 = **30.434** |
| 锥度 1:10 | 半角 = arctan(1/20) = **2°51′45″** |
| 公差 Ø40 IT7 | 上/下偏差对应公差值 **0.025 mm**（IT6 为 0.016、IT8 为 0.039） |
| 转速 Ø50、Vc=150 | n = 1000×150/(π×50) = **955 r/min** |
| 重量 Ø50×100 钢 | V = π×25²×100 = 196350 mm³ → m ≈ **1.54 kg** |

> 这 6 条能跑通，说明"公式层"是可信的；剩下的风险全在**数据表录入**上，靠 `PROVENANCE` + 社区校对解决。

## 7. 许可、合规与分发

### 7.1 你自己的 License

| 选择 | 效果 | 建议 |
|---|---|---|
| **MIT** | 最易被接受、被 fork、被推荐；对国内套壳上架无防御 | **主推**（你目的是传播与口碑） |
| **AGPL-3.0** | 套壳上架必须开源，能挡大部分抄袭；部分公司不愿用 | 若担心被拿去卖，选这个 + 商标 |
| 折中 | 代码 AGPL + 数据表 CC BY-SA + 项目名/图标做商标 | 想长期做时用 |

### 7.2 复用别人的代码：一张表说清

| 对方许可 | 能不能拷代码 | 义务 |
|---|---|---|
| **MIT-0**（CncCalculator） | 能 | 无（连署名都不要求） |
| **MIT**（ThreadBuddy / CNC-ToolHub / gears / cutcalculator） | 能 | 保留原作者版权与许可声明 |
| Apache-2.0 | 能 | 保留版权 + NOTICE + 专利授权条款（本类项目未发现） |
| **LGPL-2.1 / GPL-3.0** | 谨慎 | 会把你的 App 锁进 GPL；**只参考公式、不链代码** |
| **无 LICENSE**（约 6 个，含 `cnc-turner-friend`、`brturn`） | **不能** | 只能看功能设计；想用先请作者补 LICENSE |

> ⚠️ `Machinist_calc` 只在 README 里自称 MIT、**仓库无 LICENSE 文件**——复用前先在 issue 里请作者补齐。

### 7.3 数据与版权（最容易踩坑）

- 标准里的**数值**（螺纹尺寸、IT 公差）是客观事实，可用；**不要整表照抄竞品 App 的排版、截图、文案**。
- 每张表标标准号：GB/T 192 / 196 / 197（螺纹）、GB/T 1800.1（公差）、GB/T 1443（莫氏）、GB/T 5796（梯形螺纹）、GB/T 3098（紧固件）。
- **切削参数**是"推荐值"不是"标准值"，必须标"以试切为准"并记录数据来源（手册/刀具商样本）。
- 不要抓竞品 App 的数据包——既是版权问题，也是数据质量问题。

### 7.4 免责与上架

- 所有出程序的页面固定提示：**"代码为参考模板，上机前请核对系统、刀具、材料与安全间距。"**
- 国内安卓商店上架一般需要**软著 + 应用备案**，开源项目也建议登记（防抢注）。
- **分发优先级**：GitHub Releases（APK）→ 酷安 → 应用宝 → **F-Droid（该品类空白，天然稀缺）** → iOS（$99/年，可后置）。

### 7.5 增长渠道（这个人群不在应用商店里找工具）

抖音/快手拍"30 秒算完梯形螺纹 + 直接出 G76" > 贴吧（车工吧/数控吧）> 各地数控交流群 > 技校老师（教学场景是天然放大器）> GitHub/Gitee 双仓库 README 放动图与功能对照表。

## 附录 B · 公式速查（直接贴进代码注释）

```
转速      n  = 1000·Vc / (π·D)              [r/min]，Vc: m/min，D: mm

粗糙度    Ra ≈ 1000·f² / (8·r)              [μm]，r: 刀尖圆弧半径 mm
锥度      C  = (D−d)/L ；α/2 = arctan((D−d)/(2L))
60° 螺纹  d2 = d − 0.6495P ；d1 = d − 1.0825P ；H = 0.866P ；H1 = 0.5413P
55° 螺纹  d2 = d − 0.6403P ；d1 = d − 1.2806P ；H1 = 0.6403P

55° 三针  M = d2 + 3.1657d0 − 0.9605P

重量      m = ρ·V ；圆钢 V = πD²/4·L
六方对角  对边 s → 对角 = 2s/√3 ≈ 1.1547s ；四方对角 = √2·s
```
